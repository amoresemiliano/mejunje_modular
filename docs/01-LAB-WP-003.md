# 01-LAB-WP-003 — Persistent clients, formulas and catalog

The canonical `apps/lab` now reads clients, formulas and catalog products from the
plain PHP API. Operational arrays start empty and never fall back to fixtures.
Each directory has a separate read-only demo view. Legacy localStorage business
arrays are ignored; the existing key continues to store requirements, batch tests,
market queries, market benchmarks and activity logs.

## Persistence and pricing

`clients.php`, `formulas.php`, and `catalog-products.php` support list/detail GET,
POST, PUT with `?id=`, and DELETE with `?id=`. Parent deletes are soft deletes.
IDs are generated by the server. `business-core.php` implements shared persistence
with fixed column allowlists, prepared statements, validation and transactions.

Formula writes lock the parent on update and validate every active ingredient.
Name, category, unit, cost and supplier are database snapshots. Item cost is
quantity times the current ingredient cost; total cost is the sum of rounded item
costs; unit cost is total divided by a positive `yieldUnits` (default 1). Monetary
costs and quantities use four decimal places. Invalid items or failed SQL roll
back the entire write. Ingredient price changes affect formulas when they are
next saved; they do not retroactively change stored snapshots.

Linked variants use formula unit cost. Unlinked variants accept an explicit
estimated cost. Suggested price is cost times `(1 + marginPercent / 100)`, rounded
to two decimals. Sale price is an independently approved commercial value.
Saving a formula refreshes linked variant estimates and suggestions without
changing approved prices. Product writes replace all variants atomically and
generate new child IDs; SKU collisions produce a conflict and rollback.
Clearing a formula association sends explicit `null`.

```text
node --test tests/business-api.test.cjs
npm run build --workspace=@mejunje/lab
```

PHP tests use an isolated SQLite memory database and a test adapter that removes
`FOR UPDATE`. They exercise real SQL insert/update/delete and transaction rollback
but do not verify MySQL DDL, foreign keys, row locking or BlueHost. Node tests mock
the API transport to verify service calls, explicit mappers, payloads and demo
guards. A Next.js build does not verify browser interactions or remote runtime.

## Manual DEV validation after a separately authorized release

1. Confirm the DEV DB/schema and all four foreign keys; GET each endpoint and
   verify the normal success envelope. Check both routed and `.php` URLs.
2. Create, edit, duplicate and delete a client. Reload after each change. Confirm
   the duplicate has a different ID and deletion retains the inactive DB row.
3. Create a formula from real ingredients, with yield 10. Confirm server totals
   and cost per unit after reload. Try zero yield, a missing/inactive ingredient
   and falsified snapshot/cost values; expect rejection or authoritative values.
4. Edit formula ingredients, then submit one invalid item. Confirm parent and
   previous children remain unchanged on failure. Verify row locking with
   concurrent updates on the actual MySQL DEV environment.
5. Create a product with multiple variants and a real formula. Confirm cost comes
   from the formula, suggestion uses markup, and approved price stays independent.
   Edit the formula and confirm updated estimates with unchanged approved prices.
6. Unlink the formula and save an explicit cost. Replace variants; deliberately
   collide SKUs and confirm parent/previous variants survive the failed write.
   Soft-delete the product and verify reload.
7. Switch all three directories to demo. Confirm create/edit/duplicate/delete
   cannot mutate real data. Real formula/product selectors contain no demo IDs.
8. Simulate failed GET and failed save; verify retry, retained input, no success
   notification on failure, and a single request when repeatedly clicking Save.
9. Inspect the existing localStorage key: only the five temporary modules remain.
   Verify legacy business data is not imported, including with an unavailable API.
