---

## 4. Key Architectural Decisions

1. **Explicit Data Access Boundary**: UI components do not query Supabase directly. All data fetching flows through `apps/storefront/services/catalog.ts` and `catalog-mapper.ts`.
2. **DTO Contract Compliance**: Consumes DTO contracts exported by `@mejunje/contracts` (`CatalogProductDTO`, `CatalogVariantDTO`, `CatalogPriceDTO`, `CatalogCategoryDTO`, `OlfactoryPyramidDTO`, `CatalogMediaDTO`, `CatalogProductDetailDTO`).
3. **Public Anon Client Security**: Connects to Supabase exclusively via `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`. `service_role` keys are strictly prohibited.
4. **Quiet Error & Fallback Handling**: Database connection failures or missing environment variables fail closed gracefully, returning clean empty states without leaking raw database tracebacks to end users.
5. **Public Media Storage Strategy**: Storage URLs for `catalog-media` bucket are generated dynamically using `buildCatalogMediaUrl()` without hardcoding project domains.
